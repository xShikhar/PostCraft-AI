## 1. How the system works end to end

PostCraft is a writing workspace with a Next.js browser interface and a FastAPI backend. A user signs up or logs in, receives a seven-day JWT, and stores it in browser local storage. The shared API client sends that token with requests. In the documented production setup, the frontend calls Render directly through `NEXT_PUBLIC_API_URL`; PostgreSQL is intended to live on Supabase, while Chroma stores a searchable history of style descriptions.

The main page owns the current screen, form inputs, three drafts, selected draft, chat streams, and research links. Clicking Generate sends the topic, LinkedIn/X selection, raw thoughts, optional profile context, and background-context toggle to `POST /api/generations`. FastAPI authenticates the user, applies an IP rate limit and a separate rolling per-user daily count, finds or creates a project, and inserts a generation row. It then waits for an in-process concurrency slot and invokes `PostGenerationPipeline`.

The pipeline compiles and runs an actual LangGraph `StateGraph`. Research first checks a shared PostgreSQL cache. On a miss, it searches for creator examples and then broader examples through Tavily, or SerpApi when Tavily has no configured key. If no snippets are found, Gemini can produce simulated posts as structural examples. Pattern extraction combines the research with recent historical style descriptions and asks Gemini for structure, tone, pacing, storytelling, formatting, and CTA style. A cache hit with an existing style profile can skip this extraction. Newly extracted profiles are saved in background tasks to PostgreSQL and Chroma.

Draft generation asks Gemini for three variants using the topic, raw thoughts, style, research, and prompt rules. When enabled, a separate context builder adds the stored about-me text and selected fields from the decrypted resume summary. Resume uploads are parsed and summarized separately; their extracted text and summary are encrypted before storage. About-me and manually entered profile context currently remain plaintext in the application database. Saved profile context also enters the main prompt independently of the optional resume/about-me toggle.

The quality node runs deterministic originality, structural-tell, and unsourced-number checks, followed by a Gemini judgment of completeness, CTA, and substance. Hard failures can loop through an increment node back to drafting, at most twice. Soft failures save as `needs_review`; successful checks save as `editing`. The save node persists the three drafts and status before the HTTP response returns. Source links and the substance score are response data, but are not persisted with the generation. Several enforcement gaps described below mean these checks do not guarantee grounded, human-sounding content.

The browser displays the variants, supports copying and selecting one, and sends chat instructions to a separate editing endpoint. That endpoint retrieves only the selected draft's conversation, calls Gemini, and saves the replacement and chat messages. Finalize selects a draft, optionally derives a Preference by comparing it with a style description, deletes the generation's chat history, and marks it finalized. History can list and reopen saved generations, including chats that have not been deleted. The intended learning loop stops short: saved Preferences are never loaded into subsequent generation prompts, and the stored StyleProfiles mainly describe researched patterns rather than the user's final choices.

Primary trace: [Home.handleGenerate](<C:/Project/Ai post/frontend/src/app/page.tsx:100>) → [generate_post](<C:/Project/Ai post/backend/app/api/generations.py:24>) → [PostGenerationPipeline](<C:/Project/Ai post/backend/app/services/pipeline/pipeline.py:16>) → [build_graph](<C:/Project/Ai post/backend/app/services/pipeline/graph.py:52>) → [node_save_generation](<C:/Project/Ai post/backend/app/services/pipeline/nodes.py:691>).

### Endpoint authorization coverage

All user-data route families inspected require `get_current_user`: profile read/update/delete, resume upload/read/delete, style profile, generation create/list/full, edit and finalize. Generation reads/edits/finalization join through `Project.user_id`; profile/resume/style queries use the authenticated user ID. All four `/api/admin/*` routes require `require_admin`. I found no direct cross-user object lookup missing its ownership check in these route families. Signup/login and health endpoints are intentionally public; `/api/health/db` has the diagnostic disclosure noted below. The admin-promotion flaw bypasses the intended role-grant policy despite the presence of these checks.

## 3. Ranked problems and suggested fixes

Severity is scoped to the observed issue. “Blocking” means unsafe public access or a reproducible failure in the documented setup, not proof that the current live deployment is down. No fixes were applied.

### Blocking

1. **Public signup can obtain an allowlisted admin identity.** [auth.py:59](<C:/Project/Ai post/backend/app/api/auth.py:59>), `signup` at 74–83, and `login` at 110 promote by lowercased username. Username uniqueness/login matching are case-sensitive (`User.username`, [models.py:17](<C:/Project/Ai post/backend/app/models.py:17>)). An unclaimed allowlisted name, or a case variant under the declared PostgreSQL schema, can become admin. CLI revocation is undone on the next authenticated request while the username remains allowlisted. **Fix:** remove all environment-based promotion to meet the requested CLI-only policy; normalize usernames consistently; audit grants/revocations and review existing admins.

2. **The supplied `.env.example` is incompatible with Settings.** [config.py:96](<C:/Project/Ai post/backend/app/core/config.py:96>) uses `SettingsConfigDict(env_file='.env')` with the default `extra='forbid'`. The example's active `CHROMA_PERSIST_DIR` and `SENTRY_TRACES_SAMPLE_RATE` are undeclared Settings fields. An isolated, no-write parse of the actual sample returned `extra_forbidden` for both. `SENTRY_DSN` is also undeclared and would fail if uncommented in dotenv. Process environment variables alone do not cause the same extra-field failure. **Fix:** model the documented settings consistently or deliberately ignore unrelated dotenv keys; validate the example without importing the app or touching a database.

3. **The checked-in Render Blueprint cannot describe the repository build correctly as written.** [render.yaml:16](<C:/Project/Ai post/backend/render.yaml:16>) specifies `./Dockerfile` without `rootDir` or `dockerContext`, but the Dockerfile and its expected `pyproject.toml` are under `backend/`. It also uses `releaseCommand` at 24, whereas Render documents `preDeployCommand`. The Blueprint's location under `backend/` does not itself set the service root. [Render's Blueprint reference](https://render.com/docs/blueprint-spec) and [monorepo documentation](https://render.com/docs/monorepo-support) confirm these path/configuration rules. **Fix:** explicitly set the backend root/build context and supported lifecycle field, then validate the Blueprint. Dashboard overrides may explain a working existing service; those were not visible. `start.sh` already runs migrations before Uvicorn.

### Important

4. **Preferences are written but never used; temporal learning is unreliable.** [finalize_generation:169](<C:/Project/Ai post/backend/app/api/editor.py:169>) compares a selected draft with an unrelated “latest” profile and inserts Preference; pipeline code never queries Preference. [_build_temporal_style_bias:240](<C:/Project/Ai post/backend/app/services/pipeline/nodes.py:240>), cache reuse at 85, profile API ordering at `users.py:85`, and background pruning at `background_tasks.py:91` sort UUIDv4 IDs instead of `created_at`. Pruning can discard newer styles. **Fix:** connect generation-specific original/final draft evidence to learned preferences; retrieve those preferences in subsequent prompts; consistently sort/prune by timestamps with a tie-breaker; keep Chroma pruning in sync.

5. **Quality failures can be labeled successful.** [node_quality_check:588](<C:/Project/Ai post/backend/app/services/pipeline/nodes.py:588>) returns PASS without an LLM; exceptions at 669–681 also return PASS. That exception update does not reset all previous failure fields after a retry. The score-only feedback at 651 does not change pass/fail, and the banned-phrase category at 638 contradicts [the judge prompt:190](<C:/Project/Ai post/backend/app/services/pipeline/prompts.py:190>). **Fix:** distinguish “not evaluated” from pass; save needs-review on judge failure; reset quality state explicitly; use one category contract and explicit score policy; add a deterministic banned-phrase check if it is meant to be a hard guarantee.

6. **Grounding can be defeated by simulated research and number matching.** [research.py:143](<C:/Project/Ai post/backend/app/services/research.py:143>) asks Gemini for simulated post text. Cache writes retain only snippets, and `_check_cache` at 38–44 turns every hit into `source="cache", confidence="high"`, losing URLs and synthetic provenance. [nodes.py:543](<C:/Project/Ai post/backend/app/services/pipeline/nodes.py:543>) treats these snippets as numeric evidence. [is_number_sourced:51](<C:/Project/Ai post/backend/app/services/pipeline/unsourced_numbers.py:51>) accepts the same digits regardless of unit or whose achievement it is. A pure in-memory probe accepted “I grew revenue to $10M” with only “I have 10 years of experience” as evidence. The LLM judge receives no original inputs ([build_quality_prompt:224](<C:/Project/Ai post/backend/app/services/pipeline/prompts.py:224>)). **Fix:** preserve provenance/confidence/URLs; never use synthetic examples as factual evidence; validate claim, unit and subject together; provide authoritative inputs to the judge.

7. **Editing bypasses guardrails and blocks the async server.** [edit_generation:71](<C:/Project/Ai post/backend/app/api/editor.py:71>) uses a separate prompt without the generation rules or source/background context. Synchronous `client.models.generate_content` calls at 94 and 192 run inside async handlers, outside the shared bounded wrapper and generation semaphore. Quality gates and normal cost instrumentation are skipped. **Fix:** use an async/bounded shared LLM path, supply relevant context, and evaluate revised/final drafts before claiming readiness.

8. **A failed pipeline returns a success-shaped payload with nullable drafts.** [generate_post:116](<C:/Project/Ai post/backend/app/api/generations.py:116>) puts the error message itself into `status` and returns the normal response. [handleGenerate:120](<C:/Project/Ai post/frontend/src/app/page.tsx:120>) treats everything except `needs_review` as success, ignores `error`, and assigns nullable drafts to a string-only UI type. [DraftCard:54](<C:/Project/Ai post/frontend/src/features/editor/components/draft-selection-grid.tsx:54>) accesses `content.length`. **Fix:** define explicit success/needs-review/failure response variants; validate draft presence; surface failure without rendering draft cards.

9. **Account switching can expose the previous user's workspace on the same browser tab.** [Home state:45](<C:/Project/Ai post/frontend/src/app/page.tsx:45>) persists drafts, chats, inputs and selected view across the auth conditional. [logout:89](<C:/Project/Ai post/frontend/src/features/auth/hooks/use-auth.ts:89>) removes only the token. Reauthentication remounts child views with the previous Home state. The backend still checks ownership, but stale private content can remain visible and pending responses can update it. **Fix:** reset/key all account-scoped state on identity change, clear pending capture, and cancel/ignore requests from the prior session.

10. **Background privacy requirements are only partly implemented.** [User fields:19](<C:/Project/Ai post/backend/app/models.py:19>) and [update_me:57](<C:/Project/Ai post/backend/app/api/users.py:57>) store about-me and profile context as plaintext. [generate_post:73](<C:/Project/Ai post/backend/app/api/generations.py:73>) loads saved profile context regardless of `use_context`; [build_draft_prompt:212](<C:/Project/Ai post/backend/app/services/pipeline/prompts.py:212>) always inserts it. Resume summary/about-me injection is correctly gated separately. **Fix:** define the toggle's scope clearly, separate writing instructions from private background, enforce it consistently, and encrypt all fields covered by the requested at-rest guarantee.

11. **Resume cryptography does not satisfy the documented failure contract.** [_get_fernet:31](<C:/Project/Ai post/backend/app/core/crypto.py:31>) checks the key lazily and calls `sys.exit` during a request if invalid; it is not validated on every boot. `decrypt:87` returns the original value for InvalidToken, including corrupt ciphertext or a wrong valid key. The optional legacy migration is off by default ([start.sh:17](<C:/Project/Ai post/backend/start.sh:17>)). **Fix:** validate required cryptography configuration at startup, identify plaintext legacy data explicitly, reject corrupt encrypted records, and track completion of legacy migration before asserting all historical resumes are encrypted.

12. **Successful account deletion does not guarantee vector erasure.** [delete_my_account:301](<C:/Project/Ai post/backend/app/api/users.py:301>) tolerates vector failures and returns complete-success wording. [delete_all_for_user:148](<C:/Project/Ai post/backend/app/services/vector.py:148>) itself catches failures. [background_tasks.py:69](<C:/Project/Ai post/backend/app/services/pipeline/background_tasks.py:69>) can still write vectors from an in-flight generation after deletion. Shared research cache topics are not tied to an account and are not removed. SQL deletion does explicitly cover CostLogs in addition to ORM cascades. **Fix:** coordinate in-flight jobs with deletion, persist/retry external erasure, and report deletion status accurately; define how account-derived research data is retained.

13. **Profile background save can erase the user's writing preferences.** [handleSaveBackground:300](<C:/Project/Ai post/frontend/src/features/profile/components/profile-page.tsx:300>) writes only `resumeBackground` into `profile_context`; `handleSaveStyle:314` packs writing style into the same field using a marker. Saving background after style removes that section, despite separate UI panels implying independent settings. **Fix:** use separate structured fields or a shared merge/save function that preserves both values and accurately tracks unsaved changes.

14. **Header search fails on both routing and data contract.** [TopHeader:76](<C:/Project/Ai post/frontend/src/components/layout/top-header.tsx:76>) directly fetches same-origin `/api/generations`, bypassing the Render API URL. It expects `id`, while the backend returns `generation_id`, and at 172 navigates to `/history?open=...`, a route that does not exist. Only the first 50 items are client-filtered. **Fix:** use the shared history API with server query/filter parameters and the existing parent reopen callback, or implement a real URL route deliberately.

15. **Home metrics and quick capture are misleading/broken.** [HomeView:149](<C:/Project/Ai post/frontend/src/features/home/components/home-view.tsx:149>) requests `limit: 200` from an endpoint capped at 100 ([generations.py:136](<C:/Project/Ai post/backend/app/api/generations.py:136>)); failure is swallowed and activity/counts appear empty. Counting one returned page also cannot establish an all-time total. Capture at `home-view.tsx:189` sets session storage after navigation, but the parent reader at [page.tsx:79](<C:/Project/Ai post/frontend/src/app/page.tsx:79>) runs only when authentication changes. **Fix:** use a metrics endpoint or correct totals/pagination, show load errors separately from zero, and pass captured text through an explicit callback/state update.

16. **History cannot deliver the requested complete recall workflow.** [HistoryList:106](<C:/Project/Ai post/frontend/src/features/history/components/history-list.tsx:106>) has no search/filter/date-group state or controls. [finalize_generation:204](<C:/Project/Ai post/backend/app/api/editor.py:204>) deletes every chat for that generation. [get_generation_full:207](<C:/Project/Ai post/backend/app/api/generations.py:207>) cannot restore lost sources or scores because they were never persisted; the parent also does not clear old sources when reopening. **Fix:** wire the existing backend filters, group by date, make chat retention explicit, persist provenance/quality metadata, and clear or load all generation-specific UI state.

17. **Upload/auth/topic validation leaves avoidable resource and data failures.** [upload_resume:146](<C:/Project/Ai post/backend/app/api/users.py:146>) reads the entire upload before checking 5 MB. [extract_text](<C:/Project/Ai post/backend/app/services/resume.py:23>) permits loose MIME/extension dispatch and a Latin-1 fallback that can accept arbitrary binary; PDF/DOCX parsing is synchronous with no page/expanded-size budget. [UserCreate:30](<C:/Project/Ai post/backend/app/api/auth.py:30>) has no username/password length or normalization rules. [GenerateRequest:7](<C:/Project/Ai post/backend/app/schemas/api.py:7>) allows 500 topic characters while `Generation.topic` is `String(255)`. **Fix:** bound bytes before full parsing, restrict formats, bound extraction work, validate credentials and match API/database limits.

18. **Rate limits exist, but their scope and retry hints differ from the docs.** [auth_limiter:21](<C:/Project/Ai post/backend/app/api/auth.py:21>) is in-memory and keyed by IP for signup/login/generate/edit/finalize, not by authenticated user. Profile writes and resume upload are not decorated. The rolling 50-generation daily count is a separate non-atomic check. Header generation is not enabled in the limiter and [CORS middleware:115](<C:/Project/Ai post/backend/app/main.py:115>) does not expose Retry-After; [fetchApi:72](<C:/Project/Ai post/frontend/src/lib/api/client.ts:72>) supports that hint but generally cannot obtain it as promised. **Fix:** retain IP protection for auth, add user/shared-store budgets for costly operations, make limits atomic, and generate/expose accurate retry headers.
